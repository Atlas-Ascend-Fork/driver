# 三层递进文档模板说明

步骤4生成文档时Read本文件获取三层递进模板的详细写作要点。SKILL.md已内嵌模板骨架，本文件补充每层每节的写作要点和示例。

## 模板核心原则

**递进式抽象层次**：从宏观到微观，每层为下一层提供上下文。

- 第一层（定位）：回答"这个模块是什么、做什么、依赖谁"——读者读完后知道模块在系统中的位置
- 第二层（逻辑视图）：回答"模块内部怎么划分、子模块怎么配合"——读者读完后知道模块的内部结构
- 第三层（子模块细化）：回答"每个子模块具体做什么"——读者读完后能深入任何子模块

## 第一层：模块定位

### §一、软件栈位置

**写作要点**：

1. 画软件栈分层图（ASCII或Mermaid），标出模块所在层
2. 说明 mixed 层属性（HAL用户态+SDK内核态，两个构建产物）—— 如适用
3. 说明版本间的关系（共存、构建配置选择、演进）—— 如适用

**示例**：

```text

应用层 → HAL接口层 → [模块功能层] → 通信层 → 基础设施 → 内核适配 → Linux内核

```

### §二、主要功能与支持的特性

**写作要点**：

1. 特性清单表格（特性名+说明+关键能力，每行一个特性域）
2. 对外API说明（总数+实现文件位置+api_registry不准说明）—— 如适用
3. 硬件支持范围（哪些特性限制哪些硬件）—— 如适用

### §三、对周边模块的依赖

**写作要点**：分三类——向上(被谁依赖)、向下(依赖谁)、横向(协作谁)，每类一个表格

## 第二层：逻辑视图

### §四、子模块划分

**写作要点**：

1. HAL用户态子模块清单（表格：子目录+功能）
2. SDK内核态子模块清单（表格：按初始化阶段分组）
3. 不需要展开每个子模块的细节（第三层做）

### §五、子模块协作架构

**写作要点**：

1. 跨层桥接说明（字符设备+桥接方式+内核入口）—— 如适用
2. **Mermaid flowchart**：子模块协作架构图
3. **Mermaid sequenceDiagram**：关键协作时序
4. 时序图标注代码位置(file:line)，步骤≥10

### §六、关键设计机制

**写作要点**：提炼跨子模块共用的设计模式（6项）：

1. 自动特性加载框架（3 scope）
2. 特性数组机制（柔性数组+feature_id）
3. 范围红黑树管理（哪些模块共用）
4. 引用计数机制（Pin/Unpin，各模块的计数类型）
5. 消息通道机制（KMC+UMC）
6. 双层回收+APM退出

附公共数据结构和VA空间划分。

## 第三层：子模块功能细化

### 写作要点

1. **按功能域分组**（不按目录），每个功能域一个§节
2. 每个子模块给出：位置/阶段/职责/核心数据结构/关键函数(标注file:line)
3. **参考文档可用时优先读取对应md**丰富内容（见SKILL.md参考文档索引表）
4. 未深入分析的子模块标注`[未验证]`，不得伪造
5. 子模块间协作关系要说明（如子模块A与子模块B的协作）

### 功能域分组

功能域分组由 knowledge.md §3 子模块清单推导。skill 不内嵌任何模块特有分组。

通用写作规则：

- 按 knowledge.md §3 的子模块功能域分组，每个功能域一个 §节
- 每个子模块给出：位置/阶段/职责/核心数据结构/关键函数(标注file:line)
- 参考文档可用时优先读取对应md丰富内容（见 knowledge.md §6）
- 未深入分析的子模块标注 `[未验证]`，不得伪造
- 子模块间协作关系要说明（如子模块A与子模块B的协作）

### 每个子模块的写作模板

```text

### X.N 子模块名 — 缩写全称

**位置**: `目录路径` | **阶段**: Stage N | **职责**: 一句话

- 核心数据结构: struct xxx (字段说明)
- 关键函数: func_name (file:line) — 功能说明
- 协作关系: 与哪些子模块怎么配合
- [未验证] 标注未深入分析的部分

```
