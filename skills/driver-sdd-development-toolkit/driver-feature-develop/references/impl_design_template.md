## 章节结构对照表

| 节号 | 标题 | 内容 |
|------|------|------|
| §1 | 变更概述 | §1.1 变更点清单（变更点×类型×文件）/ §1.2 设计约束来源（需求文档+存量文档+源码） |
| §2 | 变更点详细设计 | 每个变更点：类型目标 / 涉及文件函数 / 插入点锚点 / 修改前后对比(修改类)或新增代码(新增类) / 结构体定义 / include 依赖 / 核心伪码 |
| §3 | 编码约束确认 | CK_CODE_GATE 6 项逐项确认 |
| §4 | Device 侧实现指导 | 如有：注册方式+handler伪码+约束；如无：保留标题写"无" |
| §5 | 文件索引 | 文件路径×变更类型×变更内容 |

## 写作规则

| 规则 | 说明 |
|------|------|
| **定位：精确实现方案** | 结合需求设计文档+存量文档+源码，输出可直接编码的方案 |
| **防歧义** | 修改类变更必须给出修改前→修改后对比；伪码接近实际 C 代码，逻辑完整 |
| **上下文锚点** | 每个修改点精确到文件:行号 + 上下文描述（"在 xxx 调用之后"） |
| **按变更点组织** | §2 按变更点（不按文件），每个变更点包含全部编码要素 |
| **多次生成一致** | AI 照此文档编码，多次生成结果应一致 |
| **file:line 标注** | 所有代码引用标注 `{文件名}:{行号}` |
| **伪码完整性** | 含变量声明、返回路径、错误处理，只省略日志格式等细节 |
| **Device 侧可空** | 不涉及时保留标题写"本次变更无 device 侧代码变更。" |
